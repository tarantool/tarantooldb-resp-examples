# Запуск кластера через Docker Compose

В этом руководстве показано, как запустить кластер TDB-Redis с помощью Docker Compose.

> [!NOTE]
> Развертывание TDB-Redis через Docker-образ используется в ознакомительных целях и
> рассчитано для использования в примерах документации и при тестировании.
> Для целевого развертывания используйте штатные средства установки.

## Пререквизиты

Для выполнения примера требуются:

* установленный Docker-образ TDB-Redis: пример использует локальный образ
  с тегом `tdb_redis:2x-latest` — он указан в поле `image` всех контейнеров
  в `docker-compose.yml`;
* приложение Docker Compose;
* исходные файлы примера `get_started`;
* `redis-cli` — для проверки работы (не обязателен).

> [!NOTE]
>  Есть два способа получить исходные файлы примера:
>  * Репозиторий [github.com/tarantool/tarantooldb-resp-examples](https://github.com/tarantool/tarantooldb-resp-examples/tree/release-2x/master).
>    Пример `get_started` расположен в директории `examples/get_started`.
>  * Отдельный архив [get_started.zip](https://download-directory.github.io/?url=https%3A%2F%2Fgithub.com%2Ftarantool%2Ftarantooldb-resp-examples%2Ftree%2Frelease-2x%2Fmaster%2Fexamples%2Fget_started&filename=get_started), скачанный из этого репозитория.

## Запуск стенда

Перейдите в директорию примера `get_started`:

```shell
cd examples/get_started
```

Запустите кластер TDB-Redis:

```shell
make start
```

Команда запускает стенд и дожидается готовности его портов.
Порядок запуска контейнеров определяется зависимостями между ними:

1. Запускается централизованное хранилище конфигурации — кластер из 3 узлов Tarantool;
2. Загружается конфигурация кластера в централизованное хранилище (контейнер `init`);
3. Запускаются контейнер `failover` (координатор supervised failover) и 3 инстанса TDB-Redis.

Запущенный стенд состоит из:

- кластера TDB-Redis: 1 мастер и 2 реплики (RESP-порты 46379, 46380, 46381);
- Redis Sentinel — по одному в каждом инстансе TDB-Redis (порты 36379, 36380, 36381);
- контейнера `failover` — координатора supervised failover;
- кластера централизованного хранилища конфигурации из 3 узлов.

После запуска должны работать все контейнеры, кроме [init](#контейнер-init).
Также после запуска кластер доступен для Redis-клиентов:

```shell
redis-cli -p 46379 ping                              # PONG
redis-cli -p 36379 sentinel master storages001       # статус мастера
```

## Используемые файлы

В руководстве используются следующие файлы примера `get_started`:

* `Makefile` — инструкции для утилиты `make` для запуска и остановки всего стенда;
* `docker-compose.yml` — описание всех узлов стенда;
* `init.sh` — скрипт, который выполняется в контейнере `init`;
* `wait.sh` — скрипт, который дожидается готовности кластера (вызывается командой `make start`);
* `cluster/config_storage/` — директория с файлами конфигурации централизованного хранилища:
  * `config.yaml` — топология хранилища конфигурации;
* `cluster/tdbredis/` — директория с файлами конфигурации кластера TDB-Redis:
  * `config.yaml` — адреса централизованного хранилища конфигурации;
  * `source.yaml` — топология кластера TDB-Redis, публикуется в централизованное хранилище конфигурации контейнером `init`.

## Конфигурация контейнера для узла TDB-Redis

Конфигурация контейнера для узла TDB-Redis задается в файле `docker-compose.yml`:

```yaml
tdbredis-1:
  image: tdb_redis:2x-latest
  volumes:
    - ./cluster/tdbredis:/tdb_redis/instances.enabled/tdbredis
  command: ["tarantool", "--name", "instance001", "--config", "instances.enabled/tdbredis/config.yaml"]
  ports:
    - "46379:6379"
    - "36379:26379"
```

Здесь:
* `image` — название Docker-образа, используемого для создания контейнера;
* `volumes` — директория с конфигурацией кластера, монтируется в контейнер;
* `command` — запуск инстанса Tarantool:
  * `--name` — имя инстанса из топологии в `source.yaml`;
  * `--config` — путь к файлу конфигурации;
* `ports` — маппинг RESP-порта инстанса и порта Sentinel на хост.
  Sentinel работает как роль `tdb_redis_sentinel` внутри каждого инстанса. Хост-порты выбраны вне портов
  Redis по умолчанию (6379 и 26379), чтобы стенд не конфликтовал с Redis, запущенным на хосте.

## Контейнер init

В файле `docker-compose.yml` есть специальный контейнер `init`.
С этого контейнера выполняется загрузка конфигурации кластера TDB-Redis
в централизованное хранилище: публикация топологии из `cluster/tdbredis/source.yaml`
командой `tt cluster publish`.

После успешной публикации контейнер завершает работу. Остальные узлы стартуют
по цепочке зависимостей (`depends_on`) из `docker-compose.yml`: контейнер
`failover` — после завершения `init`, инстансы TDB-Redis — после запуска `failover`.

## Остановка стенда

Остановить стенд можно так:

```shell
make stop
```
